Выполни пассивный аудит адреса: $ARGUMENTS

Правила (нарушение = провал задачи):

- Только пассивные проверки: GET-страницы, заголовки ответа, TLS, DNS. Запрещено
  предлагать и тем более запускать SQLi/XSS-сканирование, ZAP, k6, брутфорс
  путей и любую нагрузку (`docs/scope.md`).
- Инвентарь проверок и пороги — `docs/checks.md` §1. Чего нет в таблице, того нет
  и в отчёте: не добавлять «свои» проверки по ходу дела.
- Числа берутся только из `audit-report/audit_data.json`. Ты ничего не измеряешь
  и не оцениваешь «на глаз».

Шаги:

1. Собери факты (адрес подставь в кавычки, как есть):

   node scripts/audit-collect.mjs --url "$ARGUMENTS"

   Результат — `audit-report/audit_data.json`. Если exit не 0 или у сайта
   `error` не `null` — покажи ошибку и остановись, не выдумывай данные.
2. Отрендерь отчёт:

   node scripts/audit-render.mjs

   Результат — `audit-report/audit-report.html`. Рендер сам падает, если остался
   `{{`, найден внешний ресурс или файл больше 150 КБ — тогда покажи ошибку.
3. Покажи пользователю: счётчики `ok` / `warn` / `fail` / `unknown`, до трёх
   пунктов из раздела «1. Сводка» и путь к файлу отчёта.

Чего не делать:

- Не вызывать внешние API (PageSpeed, Observatory, SSL Labs): ключей нет,
  в отчёте честно стоит «не проверялось».
- Не запускать браузерный Lighthouse, трейс и сетевую запись: это ручная стадия
  вне CI (`docs/checks.md` §1.1, AUD-14), а не часть команды.
- Не править готовый HTML руками: правки живут в `templates/audit-report.html`
  и `scripts/audit-render.mjs`.
- Не закрывать этап без `node tools/check-docs.mjs` и записи в
  `Что сделано.txt` (`AGENTS.md` §6).
