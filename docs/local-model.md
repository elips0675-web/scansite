## 2. Что это значит для сканера

Отчёт-образец — 14 453 байта, то есть 4–5 тыс. токенов вывода. При 30 ток/с
это ~2,5 минуты только на вёрстку, а лимит `output` в конфиге OpenCode — 4096
токенов (`10-Приложения.txt:124`). Вывод простой: **HTML модель не пишет**.

Что пишет модель:

| Задача | Объём | Влезает |
|---|---|---|
| Раздел «Выводы» по `audit_data.json` | ≤ 300 слов | да |
| Пояснение одной находки | 2–3 предложения | да |
| Правка скрипта сбора (один файл) | до 200 строк | да, при ctx 12288 |
| «Проанализируй 20 сайтов и напиши отчёт» | 15+ тыс. токенов | нет |

## 3. Двухшаговый промпт

```
шаг 1 (локально, без модели):
  node scripts/audit-collect.mjs --sites sites.json
  # результат: audit-report/audit_data.json

шаг 2 (модель, ≤ 300 слов):
  «Прочитай audit-report/audit_data.json. Напиши раздел "Выводы": три главных пункта
   в порядке приоритета, каждый со ссылкой на id находки. Не выдумывай
   значений, которых нет в JSON. Не больше 300 слов.»
```

Именно это и советует источник (`Аудит сайтов через OpenCode Генерация
HTML-отчётов Qwen.html:258`), но с уточнением: шаблон отчёта готовит человек,
а не модель.

## 4. Что отдавать облаку

| Задача | Куда |
|---|---|
| Написать `audit-collect.mjs` с нуля | облако: 14B путает `node:tls` и `fetch` API |
| Разобрать незнакомый формат заголовков | облако |
| Раздел «Выводы» по готовому JSON | локально |
| Мелкая правка шаблона или парсера | локально |
| 20 сайтов подряд | локально, модель вообще не нужна |

Правило эскалации: если локальная модель дважды не воспроизвела результат
теста — задача уходит в облако, а не «пробуем ещё пять раз».

## 5. Подключение к OpenCode

Ключи конфигурации — V2 (`providers`, `agents`), образец с моделью
`ollama/swiftmatch-coder-14b:latest` — `10-Приложения.txt:114-160`. Свой
конфиг проекта не создаём, пока нет кода: правка `opencode.json` без скриптов
ничего не проверяет.

Альтернатива — Cline (VS Code): удобнее для диффов, но его системный промпт
съедает 3–4 тыс. токенов из 12 288 (`10-Приложения.txt:278-284`).
