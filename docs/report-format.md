# Контракт `audit-report.html`

Отчёт — один файл, который открывают двойным щелчком офлайн и печатают на A4.
Ни одного внешнего запроса: ни шрифтов, ни CSS, ни картинок, ни скриптов.

## 1. Структура документа

| Раздел | Содержимое |
|---|---|
| Шапка | адрес, дата и время прогона, версия инструмента, версия Node |
| 1. Сводка | счётчики `ok/warn/fail/unknown`, три самых важных пункта |
| 2. Безопасность заголовков | таблица: заголовок, значение, статус, что делать |
| 3. TLS | протокол, ALPN (`h2`), издатель, срок, сколько дней осталось; подраздел 3.1 — DNS: A, AAAA, MX, NS, SPF, DMARC |
| 4. Скорость | `ttfb_ms`, полное время, вес HTML, число внешних хостов |
| 5. Технологии | сигнатуры с указанием, где найдена |
| 6. SEO-периметр | `robots.txt`, `sitemap.xml`, `canonical`, `title`, `description`, `h1` |
| 7. Выводы | текст модели ≤ 300 слов, каждая рекомендация ссылается на `id` находки; подпись указывает модель, число слов и число ссылок |
| 8. Что не проверялось | активные тесты, Lighthouse, внешние API без ключа |

Порядок разделов фиксирован: сравнение двух отчётов идёт построчно.

## 2. Статусы

Четыре значения, четвёртое обязательно:

| Статус | Цвет | Смысл |
|---|---|---|
| `ok` | `#10b981` | проверено и соответствует порогу |
| `warn` | `#f59e0b` | проверено, есть замечание |
| `fail` | `#ef4444` | проверено, порог нарушен |
| `unknown` | `#6b7280` | **не смогли проверить** (нет ключа, таймаут, 403) |

Правило: `unknown` никогда не рисуется зелёным и не суммируется в «всё
хорошо». Строка «не удалось проверить» честнее ложного `ok`
(`Аудит сайтов через OpenCode Генерация HTML-отчётов Qwen.html:256`).

## 3. Бюджет

| Параметр | Предел | Почему |
|---|---|---|
| Размер файла | ≤ 150 КБ | отправляется в мессенджер без сжатия |
| Внешние запросы | 0 | открывают офлайн, иногда без интернета |
| JavaScript в отчёте | 0 | печать и чтение не должны зависеть от скриптов |
| Шрифты | системные | ноль сетевых зависимостей |
| Слов в «Выводах» | ≤ 300 | лимит локальной модели и внимание читателя |

## 4. Вёрстка

- `lang="ru"`, `<meta charset="utf-8">`, `<meta name="viewport">` — как в
  образце (`Аудит…Qwen.html:2-5`).
- Заголовки по уровням без пропусков: `h1` один, разделы — `h2`, подпункты —
  `h3`. `h3` сразу под `h1` — ошибка.
- Инлайн-CSS в `<style>`; таблицы с `border-collapse: collapse`, перенос строк
  в длинных заголовках — `word-break: break-word`.
- Печать: `@media print` убирает фон и тени, каждый раздел не рвётся посередине
  (`break-inside: avoid`).
- Текст в отчёте — только данные и формулировки из шаблона; никаких «красивых»
  оценок вроде «сайт отличный».

## 5. Шаблон и подстановка

`templates/audit-report.html` содержит плейсхолдеры вида `{{url}}`,
`{{generated_at}}`, `{{findings.hsts.status}}`, `{{summary}}`. Рендер —
`String.replace` по плоской карте значений, без шаблонизатора: ноль
зависимостей (`AGENTS.md`, правило 4).

Проверка шаблона на незаполненные плейсхолдеры — часть гейта рендера:
если в готовом HTML осталось `{{`, прогон считается проваленным.

## 6. Что в отчёт не попадает

- Токены API, внутренние адреса, IP сервера, cookie.
- Полные тела ответов и заголовки, которых нет в `docs/checks.md`.
- Персональные данные из HTML проверяемого сайта.
- Оценки, которых нет в `audit_data.json`.
