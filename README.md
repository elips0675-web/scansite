# Сканер сайтов — пассивный аудит и HTML-отчёт

Каталог `D:\OpenCode сканер сайтов`. По списку адресов инструмент собирает
проверяемые факты (заголовки, TLS, скорость, периметр SEO) в `audit_data.json`
и рендерит из него один самодостаточный `audit-report.html`.

**Состояние: Stage 1 — документация и опубликованный репозиторий**
(https://github.com/elips0675-web/scansite, коммит `c92795a`). Кода нет. В
каталоге один входной файл — `Аудит сайтов через OpenCode Генерация
HTML-отчётов Qwen.html` (14 453 байта, 268 строк): предложение внешней модели,
не реализация. Каталога `scripts/` нет, `audit_data.json` не существует, ни
одна проверка не написана.

## Зачем

Ответ на вопрос «что чинить на сайте первым». Порядок задан источником
(`Аудит сайтов через OpenCode Генерация HTML-отчётов Qwen.html:246-250`):
сначала Mozilla Observatory и SSL Labs (HSTS/CSP/TLS), затем скорость с
эмуляцией 4G, затем постоянный контроль (UptimeRobot, Snyk), периодически —
вручную (Screaming Frog, axe, ZAP).

## Три принципа

1. **Сбор данных — код, а не модель.** TTFB и заголовки не меряются «на глаз»:
   `scripts/audit-collect.mjs` пишет JSON, и два прогона сравнимы между собой.
2. **Отчёт — шаблон, а не генерация.** Пример отчёта — 14 453 байта; локальная
   14B на 3060 отдаёт 25–35 ток/с, значит «напиши HTML» = 3 минуты работы и
   риск битой вёрстки (`docs/local-model.md`).
3. **Модель пишет только раздел «Выводы»** (≤ 300 слов) по готовому
   `audit_data.json` (`Аудит…Qwen.html:258`).

## Ограничения

- Только **пассивные** проверки. Никакого сканирования SQLi/XSS и никакой
  нагрузки (`Аудит…Qwen.html:145`, `:221-223`, `:256`).
- Проверяем свои сайты или сайты с письменным разрешением владельца.
- Внешние API (PageSpeed, Observatory, SSL Labs) видят только публичные адреса;
  `localhost` и внутренняя сеть проверяются локально (`:257`).
- Секреты — только `.env`, в репозитории `.env.example` (появится с AUD-06).
- Отчёт — один файл без внешних запросов: его открывают офлайн и печатают.
