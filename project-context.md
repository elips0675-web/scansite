# Контекст проекта — сканер сайтов

Один файл на вопросы «что за стек», «почему так», «где что лежит». Правила
работы — `AGENTS.md`, карта документов — `docs/README.md`.

## 1. Задача

По списку адресов собрать пассивные факты о сайте и отдать заказчику один
HTML-файл с приоритетами: что ломает безопасность и скорость в первую очередь.
Не «оценка красоты», а проверяемые значения: код ответа, наличие HSTS, срок
сертификата, TTFB в миллисекундах.

## 2. Стек

| Слой | Решение | Почему |
|---|---|---|
| Сбор | Node 24 (`fetch`, `node:tls`, `node:fs`) | уже стоит; `openssl` и `whatweb` на машине нет |
| Рендер | шаблон HTML + подстановка, без шаблонизатора | ноль зависимостей, детерминированный вывод |
| Выводы | локальная модель (Ollama) или облако | текст о числах, а не сами числа |
| Отчёт | один HTML-файл, инлайн CSS | открывают офлайн, отправляют в мессенджер |
| Вход | `sites.json` | список адресов в git, без кода |

Python 3.14 на машине есть, но **не используется**: два рантайма в одном
проекте дают две инструкции запуска и две причины «не работает».

## 3. Решения и даты

1. **16.11.2026. Числа собирает код, текст пишет модель.** Обоснование:
   `Аудит сайтов через OpenCode Генерация HTML-отчётов Qwen.html:258` —
   «не просите модель проверить всё сразу и написать отчёт». Для 14B на 3060
   это ещё и ~3 минуты генерации на 14 453 байта отчёта.
2. **16.11.2026. Node вместо curl/openssl/whatweb.** `openssl` и `whatweb`
   отсутствуют (`Get-Command` 16.11.2026), PowerShell-алиас `curl` не понимает
   `-sI`, а `whatweb` — Ruby-гем и на Windows не ставится.
3. **16.11.2026. Только пассивные проверки.** Основание:
   `Аудит…Qwen.html:145`, `:221-223`, `:256`.
4. **16.11.2026. Один каталог — один инструмент.** К SwiftMatch не
   подключаемся: там свои правила, свои гейты и свой бэклог.
5. **16.11.2026. Документация по схеме `D:\October CMS`.** Причина: схема уже
   проверена на двух проектах владельца (single-entry `AGENTS.md`, карта
   `docs/README.md`, журнал плюс чистый бэклог, срез `test/Для анализа.txt`).
6. **16.11.2026. Репозиторий опубликован:** `https://github.com/elips0675-web/scansite`,
   ветка `main`, подпись коммитов `elips0675-web`, доступ по HTTPS через
   Git Credential Manager.

## 4. Структура: факт и план

## 6. Чего здесь нет и не будет без нового пункта бэклога

- Активного сканирования (SQLi/XSS), нагрузки, брутфорса.
- Краулера на весь сайт: Screaming Frog остаётся десктопным инструментом.
- Веб-интерфейса, БД и мобильного приложения: результат — файлы.
- Хранения истории в базе: сравнение идёт по двум JSON-файлам.
