🚀 Аудит сайтов через OpenCode: Генерация HTML-отчётов

Да, это возможно. OpenCode специально спроектирован для оркестрации CLI-инструментов и создания артефактов. Вы можете прописать промпт в виде кастомной слэш-команды (например, /audit) или попросить агента написать Python-скрипт, который соберёт данные из вашего списка и сгенерирует готовый HTML-отчёт.

Контекст пользователя: При работе с локальными моделями на RTX 3060 (12GB VRAM) разбивайте задачу на этапы (сбор данных → генерация HTML), чтобы избежать переполнения контекста.

🎯 Вариант 1: Кастомная слэш-команда (Рекомендуемый)

Создайте файл commands/audit.md в папке ~/.config/opencode/commands/ или .opencode/commands/ со следующим содержимым:

---
description: Пассивный аудит сайта (скорость, безопасность, SEO) с HTML-отчётом
agent: build
---
Проанализируй публичный сайт по адресу: $ARGUMENTS

Выполни следующие шаги, используя доступные shell-инструменты. 
⚠️ НЕ выполняй активное сканирование уязвимостей (SQLi, XSS) или нагрузочное тестирование без явного разрешения.

1. **Технологии и заголовки:** 
   - Выполни `curl -sI $ARGUMENTS` для проверки HTTP-заголовков (HSTS, CSP, Referrer-Policy).
   - Если установлен `whatweb`, выполни `whatweb $ARGUMENTS`.
2. **SSL/TLS:** 
   - Проверь базовые данные сертификата через `openssl s_client`.
3. **Скорость (TTFB):** 
   - Зафиксируй время ответа: `curl -o /dev/null -s -w "TTFB: %{time_starttransfer}s\nTotal: %{time_total}s\n" $ARGUMENTS`.
4. **Внешние API (пассивно):** 
   - Сделай запрос к Mozilla Observatory API (POST + GET по hostname).
   - Если есть API-ключ, запроси данные через Google PageSpeed Insights API.

На основе собранных данных составь структурированный HTML-отчёт. 
Используй инлайн-CSS для стилизации (светлая тема, чёткая типографика, цветовая индикация статусов). 
Отчёт должен содержать разделы: «Технологии», «Безопасность заголовков», «SSL», «Скорость» и «Выводы». 
Сохраните итоговый отчёт в файл `audit-report.html` в текущей директории.

Использование: В интерфейсе OpenCode просто наберите /audit https://example.com

📦 Вариант 2: Python-скрипт оркестрации

Если проверок много, попросите OpenCode: "Напиши модульный Python-скрипт на asyncio + aiohttp, который опрашивает API PageSpeed Insights, SSL Labs и Mozilla Observatory для заданного URL, а затем рендерит красивый HTML-отчёт через Jinja2 с Tailwind CSS". Это надёжнее для больших объёмов данных, чем чистый shell в промпте.

🛡️ Интеграция инструментов из вашего списка

Не все инструменты из документа можно автоматизировать через OpenCode. Вот реалистичная карта автоматизации:

Категория Инструмент (из документа) Авто-через OpenCode Как реализовать
Производительность PageSpeed Insights API HTTP-запрос к Google API (нужен ключ)
cURL (TTFB) CLI Команда curl -w
WhatWeb CLI Команда whatweb url
Chrome DevTools / Lighthouse CI Сложно Требует headless-браузера, лучше вынести в отдельный Node.js скрипт
Безопасность Mozilla Observatory API POST/GET запрос к api.security.mozilla.org
SSL Labs API Запрос к ssllabs.com/api/v3/analyze
Security Headers / REDbot CLI Анализ вывода curl -I на наличие HSTS, CSP, Vary
OWASP ZAP / k6 Нет (Опасно) Требует активного сканирования/нагрузки. Только с письменного разрешения владельца!
SEO / Тех. W3C Validator API SOAP/REST API валидатора
urlscan.io API API для поиска сторонних скриптов и поддоменов
Screaming Frog / Sitebulb Нет Десктопные приложения, не автоматизируются через CLI OpenCode

💡 Рекомендованная стратегия проверок (из документа)

  1. Первым делом: Mozilla Observatory + SSL Labs. (Цель: выявить отсутствие HSTS/CSP, подтвердить TLS 1.3).
  2. Затем: Lighthouse / PageSpeed Insights с эмуляцией 4G. (Главный резерв часто в картинках и блокирующих скриптах).
  3. Постоянный контроль: UptimeRobot + Snyk (в CI/CD).
  4. Периодически (вручную): Screaming Frog (обратить внимание на sitemap 2018 года!), axe DevTools, OWASP ZAP (пассивно, раз в месяц).
  5. После любых изменений: PageSpeed Insights для контроля динамики.

⚠️ Важные ограничения

  • Пассивный анализ: OpenCode — оркестратор, а не сканер уязвимостей. Он не будет самостоятельно проводить активное сканирование (SQLi, XSS) или нагрузочные тесты без явных инструкций и соответствующих локальных инструментов.
  • Локальные сайты: Внешние API (PageSpeed, SSL Labs) не увидят внутренние ресурсы (например, nlb из вашего документа). Для них используйте локальный запуск lighthouse-cli или curl, инициируемый OpenCode.
  • Управление контекстом (RTX 3060): Не просите модель "проверить всё сразу и написать отчёт". Сначала дайте команду собрать данные и сохранить их в audit_data.json. Затем вторым промптом попросите: "Прочитай audit_data.json и сгенерируй HTML-отчёт". Это гарантирует качество и избежит обрывов генерации.
Сформировано на основе анализа документа «Инструменты для проверки.docx» и архитектурных возможностей OpenCode / локальных LLM.
