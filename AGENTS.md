## 4. Главные правила

1. **Факт — только `file:line`** открытого файла или вывод команды. «Работает»
   без прогона — не работает.
2. **Сбор данных не доверять модели.** TTFB, коды, заголовки, сертификат —
   детерминированный код. Модель их не «оценивает» и не выдумывает.
3. **HTML не генерируется моделью.** Отчёт — шаблон плюс подстановка значений.
   Модель пишет только раздел «Выводы».
4. **Ноль зависимостей на старте.** `fetch`, `node:tls`, `node:fs` хватает для
   этапов 1–2. Новая зависимость — отдельный пункт бэклога с обоснованием.
5. **Только пассивно.** Никаких ZAP, k6, брутфорса, нагрузки. Чужой сайт —
   только с письменным разрешением (`docs/scope.md`).
6. **Один сайт не валит прогон.** DNS/TLS/timeout по одному адресу — статус
   `unknown` в JSON, остальные собираются до конца.
7. **`unknown` — не `ok`.** Не смогли проверить — так и пишем; в отчёте это
   отдельный цвет, а не зелёный.
8. **Секреты — только `.env`.** Ключи PageSpeed/API в репозиторий не попадают,
   в документации — только имена переменных.
9. **Отчёт самодостаточен.** Ноль внешних `<link>`, `<script>`, `<img>`: файл
   открывают офлайн и печатают.
10. **Чужой проект не трогать.** Правка SwiftMatch или October CMS из этого
    каталога — не задача сканера.

## 5. Гейты

Перед закрытием этапа — exit 0:

```powershell
npm.cmd run check:docs                        # карта документации, бэклог, заглушки
node --check scripts/audit-collect.mjs    # после AUD-01
node scripts/audit-collect.mjs --self-test # после AUD-01: фикстура вместо сети
npm.cmd run check:docs                        # повторно, после правок бэклога
```

Пока кода нет, живой гейт один — `check:docs`. Новая команда дописывается сюда
в тот же день, когда появился скрипт, иначе гейт существует только в этом файле.
